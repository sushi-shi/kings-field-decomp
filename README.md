# King's Field

Binary-matching decompilation of the original Japanese King's Field
(`SLPS-00017`), comprising the independently linked `PSX.EXE`, `GAME.EXE`,
and `OPEN.EXE` programs. An address always belongs to one image.

## Quickstart

```sh
nix develop
kf init --retail-dir /path/to/hash-identical/retail
kf build
kf analyze
kf status
```

Supply retail game files locally. `kf build` produces the three executables;
`kf analyze` refreshes comparison objects and checks reconstruction;
`kf status` reads current results. Existing data and section-placement failures
remain under investigation. Exact function matches, exact data owners, and
executable similarity are separate measurements.

See [build commands](docs/build-system.md), [toolchain setup](docs/toolchain.md),
and [editor, emulator, and audit tools](docs/development-tools.md).

The three byte columns show similarity, not differences. Island scores allow moved regions and
small internal edits; unmatched bytes lower the score and no addresses are masked.
They exclude EXE headers and include sector padding. These describe the current source-to-EXE
outputs, but similarity is not exactness, historical tool attribution, or runtime equivalence.
Data modules exact counts complete source data-owner passes / compared owners from `kf verify data`,
including bytes, relocations, BSS layout and retail placement. Separate config-owned SDK contributions
are excluded. These strict object checks are independent of the generated executable scores.
Missing or stale outputs show —. See [the linking guide](docs/executable-linking.md)
for the algorithm, scope and per-image interactive reports.
