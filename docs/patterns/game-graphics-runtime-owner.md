## Production result

The complete owner is now `KfGraphicsRuntimeGame game_graphics_runtime`, defined
once under `DATA(0x80070e98, 0x249cc)` in `game.render`. Its header checks all
39 field offsets and the complete extent. Thirty-five former interior identities
become fields or unresolved storage spans. The 342 reviewed HI16/LO16 rows change
only `target_name`: every numeric destination, instruction site, low opcode,
status and provenance remains identical. Safe delinking and raw re-encoding of
all 342 pairs recover the original retail instructions.

Fresh production objdiff closes `item_load_floor_placements` (432 bytes),
`render_enqueue_sprite` (592 bytes), and `render_actor` (532 bytes) at strict
100%. GAME moves from 324/362 to 327/362; OPEN remains 106/108, PSX 1/1.
The three new exacts and refreshed input hashes for all 431 previously banked
exact functions are recorded with `kf bank`; all partial baseline rows remain
unchanged. Thirty-five GAME and two OPEN functions remain open. No vendored routine enters
the game denominator; all thirteen vendored verification bodies remain exact.

The campaign's complete units contain 173 functions: 79 direct consumers and
94 independent siblings. Raw comparison preserves all 149 previously exact
bodies and gains three, for 152 exact bodies. All ordered calls match retail,
and all 94 independent siblings remain byte-identical to their prior forms.
The retained production test freshly compiles all 35 units, compares all 173
target bodies directly to retail, checks source calls, requires all 152 exact
source bodies to match every word, and rejects a four-byte graphics-root shift
for every exact body using it. Historical separate-owner, narrow-owner, count-
pointer, reversed-environment and wrong-referent controls remain executable.

Canonical source was also compiled with native, debug, instrumented and repeated
instrumented GCC 2.5.7. All four complete ELF objects agree for each newly exact
function's unit. Repeated traces are byte-identical: 5,946 events for the floor
loader, 11,406 for sprite enqueue, and 8,369 for actor rendering. Each resulting
body relinks to every retail word. Instrumented compiler source fingerprint:
`ea9c07d5f5a67e28a6e3bfd21c5c53607543832a9be6561329591d0433f521fa`.
This verifies trace passivity for the retained source; it does not prove the
retail compiler's historical identity.

## Verification and limits

`ruff check scripts tests` and all 705 repository tests pass (9 skips).
`nix flake check -L` passes, including the 705-test packaged suite (146 skips
because local retail/build fixtures are absent). The full `kf build` freshly
rebuilds affected source and confirms the strict counts with zero artifact
failures and no banked-function regression. Target relinking remains GAME
75/77 units, OPEN 34/38 and PSX 1/1.

The full build still fails its data and placement checks. Data comparisons are
GAME 10/41 units, OPEN 3/19 and PSX 0/1. In `game.render`, the complete graphics
symbol has the measured 149,964-byte size in both objects, but the probe's
COMMON lowering rounds the source BSS section to 149,968 bytes. Its 16-byte
section alignment also conflicts with the eight-byte-aligned retail base.
The existing render switch-table addend difference remains. These are visible
unresolved results; no extra field, assembly, alignment override, compiler flag
or changed target byte was introduced to hide them.

Registry capacity and the projection/morph subobject extents remain unresolved.
The typed views start at decoded addresses, including the morph base
`800930f0` with copies beginning at element one. Neither neighbor distances nor
OPEN's layout justify guessed GAME capacities. The complete graphics declaration
and TU name remain WIP historical models even though the three function bodies
are exact.

Generated dossiers, before/after raw comparisons, canonical traces, relocation
audit and check logs are under `build/gcc257/graphics-owner-migration/`; they are
not committed. Durable positive and negative controls live in
`tests/test_game_graphics_owner_probe.py` and the related data inventory tests.
